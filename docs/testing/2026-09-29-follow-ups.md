# 추가 개선 후보

현재 alpha를 병합하되 공개 배포 전에 다음 항목을 추적한다.

1. 해결됨 (schema 3 / 감사 커서 v2): low seq=1보다 high seq=2가 먼저 전달되면 inbox의 seq 커서를 2로 진행한 이후 늦게 전달된 1은 증분 감사 조회에서 누락된다. receive 자체의 전달 누락은 아니다. 최초 전달 순서 기반 별도 커서를 구현했다. 업그레이드 시 기존 커서는 0부터 다시 조회한다.
2. 재현됨: low 100개로 수신 큐가 가득 차면 urgent도 inbox_full로 거절된다. 현행 용량 계약에 부합하지만 긴급 예약 용량 및 발신자별 점유 제한을 검토해야 한다.
3. 등록 성공 뒤 응답 유실·credential 파일 저장 실패에 대비한 등록 재시도 키 및 관리자 재발급 절차가 없다.
4. queue_status의 내부 SELECT *가 필요 없는 본문까지 읽는다. 메타데이터 쿼리와 실제 전달 본문 조회를 분리한다.
5. 일반용 모델 없는 wait 명령, 실패 메시지 조회·재전송·진단 도구와 설치용 플러그인/스킬은 후속 범위다.
6. Claude/OpenCode 실제 연동, native 세션 재개 및 동시 호스트 실행, 원격 Linux CI 검증은 별도로 완료해야 한다.

앞의 두 항목은 임시 DB에서 재현했다. 이후 1번은 수정했으며 2번은 후속 범위로 유지한다. Git 원격은 아직 등록되지 않았으며 npm package는 private 상태다.
