# 구조 안내

두레박은 같은 컴퓨터에서 동작하는 Cooperative 협업 런타임입니다. 지원 계약은 [구현 현황](IMPLEMENTATION.md), 사용 절차는 [사용법](USAGE.md)을 기준으로 합니다.

## 구성과 책임

- CLI는 서버 실행, 세션 등록, 메시지·작업·기록 명령을 제공합니다.
- MCP stdio bridge는 호스트 도구 호출을 인증된 로컬 HTTP 요청으로 전달합니다.
- 런타임은 credential과 workspace를 확인하고 큐 정책·작업 상태 전이를 적용합니다.
- SQLite WAL 저장소는 메시지, 작업, 산출물과 이벤트를 보존합니다.
- 호스트별 설정 어댑터는 Codex·Claude Code·OpenCode 연결 설정을 생성합니다. 실제 호스트 검증 범위는 [호환성](COMPATIBILITY.md)을 따릅니다.

## 요청과 결과

1. 발신 세션이 수신 세션을 지정해 메시지를 저장합니다.
2. 수신 세션이 직접 `receive`를 호출하면 중요도·대기 시간·상태에 따라 전달 가능한 메시지를 받습니다.
3. 수신 세션이 반환된 id·receipt로 `ack`합니다. 읽음 확인은 작업 수락이나 완료와 별개입니다.
4. 작업 담당자는 원자적 claim과 version 확인을 거쳐 결과를 제출합니다.
5. 산출물은 내용 hash로 보존되며 제한된 크기로 조회하거나 작업 기록으로 내보낼 수 있습니다.

중복 전송은 idempotency key로 억제하며 외부 도구 부작용의 exactly-once를 보장하지 않습니다. `completed`는 결과 제출 상태이며 독립 검증 성공을 뜻하지 않습니다.

## 저장과 권한

새 설치의 기본 데이터 위치는 `~/.durebak`입니다. 실제 경로와 기존 데이터 위치 처리, credential·기록 내보내기는 [사용법](USAGE.md)을 따릅니다. 캐시는 파생 조회 결과이며 원본 기록과 구분합니다. 자동 학습이나 자동 맥락 주입은 제공하지 않습니다.

서버는 인증된 loopback 연결만 허용합니다. 같은 운영체제 사용자에 속한 프로세스를 서로 격리하는 sandbox는 아닙니다. [보안 정책](../SECURITY.md)을 확인하세요.

자동 세션 깨우기, native 대화 재개, Managed 실행과 무인 반복 스케줄러는 지원하지 않습니다. 큐 저장이 호스트 실행을 자동으로 시작하지 않습니다.
