# 두레박의 제품 컨셉

## 한 문장

**두레박은 각 에이전트 세션의 맥락에서 필요한 결과를 길어 올려, 서로의 작업을 더 나아지게 하는 협업 도구다.**

## 이름과 표기

| 항목 | 표기 |
|---|---|
| 한국어 | 두레박 |
| 영문 브랜드 | Durebak |
| CLI·코드 식별자 | durebak |
| 프로젝트 설정 디렉터리 | .durebak |
| 한국어 소개 문구 | 각자의 깊이를 길어, 함께 더 나은 결과로. |
| 영문 소개 문구 | Connect agent sessions. Build better together. |
| 설명용 분류 | Local orchestration for coding-agent sessions |

브랜드와 CLI 표기는 통일한다. 설치 패키지 이름이 이미 사용 중이라면 scope나 배포 식별자를 조정한다. 외부 이름 사용 가능 여부는 아직 확인하지 않았다.

## 이름에 담는 의미

두레박이 물을 길어 올리듯, 두레박은 각 세션이 가진 작업 맥락에서 필요한 결과를 가져온다. 결과는 상대의 검토와 검증으로 이어지고, 피드백은 다시 원래 세션의 수정 작업으로 돌아간다. 여기서 물과 우물의 비유는 제품이 지향하는 경험을 설명한다.

제품의 세 가지 동작은 **길어 올리기 → 주고받기 → 함께 다듬기**다.

1. **길어 올리기:** 상대 세션의 전문성과 작업 결과를 필요한 질문으로 끌어낸다.
2. **주고받기:** 발신자·수신자·요청·산출물을 연결해 맥락 있는 대화를 유지한다.
3. **함께 다듬기:** 검토와 검증을 반영하여 결과를 수정하고 배움을 남긴다.

## 사용자에게 주는 약속

“이 세션에서 하던 일을 저 세션에 설명하고, 답변을 다시 복사하고, 어느 파일을 검토했는지 맞추는 일”을 줄인다. 사용자는 목표·참여자·완료 기준·한도를 정하고, 두레박은 그 범위 안에서 대화와 후속 실행을 이어 준다.

Claude Code, Codex, OpenCode는 각자의 강점과 맥락을 유지한다. 어느 도구든 질문자·작업자·검토자·검증자가 될 수 있다. 역할은 run별로 정하며 Provider 이름으로 고정하지 않는다.

## 대표 경험

사용자가 “이 결함을 고치고 다른 세션에서 검토·검증까지 이어 줘”라고 요청한다. 작업 세션이 결과 revision을 제출하면 검토 세션은 그 revision에 구체적인 수정 사항을 연결한다. 원래 작업 세션이 수정하고, 새 revision을 다시 검토·검증한다. 사용자는 무엇이 바뀌었고 왜 끝났는지 확인한다.

대기 중인 세션을 자동 실행할 수 없는 환경에서는 그 한계를 표시한다. 보내짐·읽음·수락·완료를 구분하고 결과가 불확실하면 사용자에게 드러낸다.

## 반복 개선의 두 층

**한 작업 안의 개선:** 작업 → 검토 → 수정 → 재검증을 완료 조건 또는 실행 한도까지 반복한다.

**다음 작업을 위한 개선:** 효과 있었던 절차와 실패 원인을 출처와 함께 기록하고, 채택한 내용만 다음 협업에 활용한다. 기록에는 적용 범위와 버전이 있어야 한다. 모델 자체가 학습됐다고 표현하지 않는다.

## 표현 원칙

- 차분하고 구체적으로 설명한다. 모든 세션을 언제나 자동 제어할 수 있다고 약속하지 않는다.
- “누가 누구에게 무엇을 요청했고 지금 무엇을 기다리는지”가 드러나게 한다.
- API와 CLI에는 session, message, task, artifact, workflow 같은 명확한 용어를 쓴다.
- 브랜드 비유를 명령어 전체에 강제로 적용하지 않는다.
- “설계됨”, “구현됨”, “실제 도구로 검증됨”을 구분한다.

기능의 기준 문서는 [제품 스펙](superpowers/specs/2026-09-29-durebak-design.md)이다.

## 적게 전달하고 오래 활용하기

두레박은 필요한 만큼 길어 올린다. 작업 기록과 근거는 충분히 남기되 세션에는 현재 역할에 필요한 요약·변경분·참조를 전달한다. 상세 내용은 필요할 때 찾아 읽고, 같은 자료의 가공은 유효한 캐시로 재사용한다.

기록은 원본 근거, 현재 상태, 결정, 배움으로 나눈다. 사람이 읽는 문서는 구조화된 기록에서 만들며 매번 모델에게 다시 쓰게 하지 않는다. 다음 세션은 전체 대화 대신 짧은 색인과 관련 기록으로 시작한다.

이 효율화가 오래된 결과의 재사용이나 검증 생략으로 이어지지 않아야 한다. 목표는 **더 적은 반복으로 같은 기준을 충족하는 것**이다. 비용 절감 여부는 실제 사용량과 품질을 함께 측정한다. 상세 내용은 [토큰·캐시·기록 설계](CONTEXT-CACHE-RECORDS.md)에 있다.
