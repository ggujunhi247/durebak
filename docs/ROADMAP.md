# 두레박 로드맵

> 구현 상태: cooperative alpha의 실제 지원 범위는 [구현 현황](IMPLEMENTATION.md)을 따른다. 이 문서의 자동 실행·고급 맥락 기능은 목표 설계다.
현재 단계는 **컨셉과 제품 스펙 정리**다. 아래 단계는 구현 범위와 출시 조건이며 실제 완료를 뜻하지 않는다. 세부 구현 계획은 검토된 제품 스펙을 바탕으로 작성한다.

## 0. 컨셉과 요구사항

- 브랜드: 두레박 / Durebak / durebak.
- 첫 범위: 같은 컴퓨터의 여러 세션.
- 목표: 통신 → 결과 교환 → 반복 개선 → 배움 재사용.
- 산출물: README, 제품 컨셉, 스펙, 아키텍처, 협업 예제.

완료 기준: 사용자 의도와 구현 범위가 문서에서 일치하고, 제안과 검증된 사실이 구분되어 있다. 문서는 작성되었으며 설계 검토 대상이다.

## 1. Provider 호환성 검증

세 도구에서 세션 시작·같은 세션 후속 실행·이벤트 수집·중단·승인 대기를 확인한다. 기존 세션 참여와 Managed 실행은 각각 기록한다.

acpx/ACP 실행 backend와 직접 Provider 경로를 같은 계약 시험으로 비교한다. 재사용 여부는 단일 소유권, 승인, 취소, 재개, replay 분리, 로컬 설치와 라이선스 검토를 통과한 뒤 결정한다.

완료 기준: 실제 버전과 OS를 명시한 capability 표가 있고 지원하지 못하는 동작이 드러난다.

## 2. 통신 기반

세션 등록, workspace 권한, 영속 우편함, 요청/응답 연결, MCP/CLI, 이벤트 재생을 구현한다. crash와 중복 전송 시험을 포함한다.

완료 기준: 같은 도구 간 왕복과 세 도구 사이 6방향 메시징이 동작한다. 통신 실험판은 자동 오케스트레이션과 구분해 표시한다.

## 3. 자동 후속 실행

Managed 어댑터, 세션별 단일 실행 소유권, 실행 대기열, 응답 후 재개, 불확실한 실행 복구를 구현한다.

완료 기준: 사용자가 메시지를 복사하지 않아도 A가 B에게 질문하고 B의 답변을 받아 같은 세션에서 이어서 작업한다. 중복 실행과 순환 대기를 통제한다.

## 4. 반복 개선

산출물 revision, 검토 발견 사항, 검증 근거, 수정 라운드, 한도와 중단, 채택된 배움 기록을 연결한다.

완료 기준: 세 도구가 작업·검토·검증 역할을 바꾸어 수행하며 최소 한 번의 수정 후 최신 revision과 policy digest의 근거로 완료한다. 무진전, 예산 소진, checkpoint 복구, 정책 변경도 시험한다. 단일 세션·메시징만 사용한 협업·검증 루프의 비교 결과를 fixture별 최소 3회 기록하며 개선 여부를 숨기지 않는다.

## 4.1 효율과 기록

역할별 2,000 추정 토큰 목표·16 KiB 자동 전달 상한, 범위 조회, delta base, 내용 hash 캐시, 결정적 문서 생성과 기록 색인을 구현한다. Provider cache 제어와 LLM 요약은 지원·정책에 따른 선택 기능이다.

완료 기준: 기본 문서 생성과 대기 관리에 모델 호출이 없고, 원문·권한·정책 변경이 cache를 무효화한다. 같은 workflow의 전체 전달/변경분/캐시 조건을 최소 3회 비교해 비용과 품질을 함께 기록한다. 세션 자체의 전체 입력 한도를 제어한다고 주장하지 않는다.

## 5. v0.1 공개 배포

설치·제거, 기존 설정 보존, 진단, GitHub Release, 패키지 배포, 호환 표, 라이선스, 기여 문서를 갖춘다.

완료 기준: [제품 스펙](superpowers/specs/2026-09-29-durebak-design.md)의 AC-01~36 충족과 실제 도구 E2E 결과. 깨끗한 지원 환경에서 문서만 보고 첫 왕복을 재현할 수 있다.
